## 明天的三步

### 1. 设定大纲：定义 game scope，分为几个大类
目标：把"游戏到底包含什么"切成清晰的大类，每类标明 MVP 做什么、以后做什么。

建议讨论的大类草案（以设计文档为基础，待确认）：

| 大类 | 内容 | 对应现有代码 |
|---|---|---|
| A. 门派经营 | 银两/声望/设施/弟子编制、日常开支 | Sect（部分） |
| B. 弟子培养 | 招收、资质、修炼、师徒、忠诚与去留 | Disciple / Growth（已有基础） |
| C. 武学 | 武学树、研修、装配、克制 | 未开始 |
| D. 江湖 | 地图节点、势力、关系值、外交 | 未开始 |
| E. 火并与战斗 | 战前布阵、自动战斗、战报 | 未开始 |
| F. 招降与俘获 | 斩/放/收、残篇、仇家 | 未开始 |
| G. 事件与叙事 | 事件库、季度大事件、结局 | 未开始 |
| H. 系统层 | 存档、设置、新手引导、本地化 | 未开始 |

产出：`docs/scope.md`，每个大类写清：MVP 范围、依赖关系、优先级（P0/P1/P2）、验收标准。

需要在讨论中拍板的问题：
- 各大类的 MVP 深度（例如江湖是 5 个势力还是 3 个？）
- 优先级顺序与里程碑划分
- 设计文档里待决的 5 个问题（美术风格、主线剧情、失败条件、世界观、引擎已定）

### 2. 由大纲确定 UI 内容
- 每个大类对应哪些页面/面板/弹窗，列成清单（页面地图）
- 确定导航结构（现在是 5 个一级页面，是否需要二级）
- 对每个页面写出：展示什么数据、玩家能做什么操作、依赖哪些 Game 接口
- 产出：`docs/ui-map.md`（页面清单 + 简单线框说明）

### 3. 改善 UI
基于上一步的页面清单，优先处理：
- 现有页面的体验问题（批量安排修炼、排序/筛选名册、可读性）
- 通用组件抽取（数值条、标签、面板、弹窗、提示）
- 内置中文字体（目前依赖系统字体回退）
- 按需搭建新页面的空壳（先有导航与布局，数据后接）
